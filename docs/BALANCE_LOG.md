# 밸런스 기록 (BALANCE_LOG)

원칙: 템포 수치(조리·식사·인내심·이동 속도·연출 시간)는 GDD 값 그대로. 바꾼 것은 `src/data/` 의 **비용과 조건(티어 매출 기준)** 뿐이다.
`tools/set-balance.py` 가 data 파일과 `tools/progression_model.py` 의 PLAN·티어·귀빈 비용을 한 번에 바꾼다. GDD 7·9·10·11장 표와 11.1 표도 같이 고쳤다.

## 2026-11-10 — 6단계 봇 검증

### 0. 구현 쪽 수정 (수치 변경 아님, 봇 결과를 보기 전에 고친 버그·흐름 문제)
| 문제 | 증상 | 수정 |
|---|---|---|
| 서버 둘이 배식대 앞에서 교착 | 직원 풀세트인데 하루 2팀 | 끼임 판정을 "남은 경로가 줄지 않은 시간"으로, 집는 지점은 다른 서버와 0.82칸 이상 떨어지게 (PROGRESS 5단계 분석) |
| 서버가 배달 대상 주문을 예약하지 않음 | 같은 메뉴 든 두 서버가 같은 테이블로 → 헛걸음 | 들고 있는 그릇마다 주문 하나씩 예약 |
| 다 먹은 손님 무리가 출구까지 걸으며 통로를 막음 | 서버 이동 시간의 40%가 막힘 | 행복 퇴장 = 통로로 나와 뿅 (화난 손님은 빠른 걸음으로 출구까지) |
| 봇 행동 예산 상한 1 | 메뉴가 2개가 되면 조리(2행동)를 영영 못 함 → 0.9 봇 0그릇 | 상한 = 최대 행동 비용(2) |
| 봇이 모든 국밥을 직접 서빙 | 친절도 평균 3.8~6.6 → 별점 4.2 정체 | 서버가 있으면 서버에게 맡기고, 인내심 38% 이상 쓴 테이블이나 배식대에 6초 이상 남은 국밥만 직접 (현명한 플레이어 흉내) |
