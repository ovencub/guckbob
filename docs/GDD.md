# 고양이 국밥집 (GuckBob) — 게임 기획서

> 이 문서의 모든 수치는 `src/data/` 의 데이터 테이블로 옮겨져야 하며, 코드 안에 숫자를 직접 박지 않는다.
> 경제·진행 수치는 `tools/progression_model.py` (일별 진행 모델)로 1차 검증했다. 이 모델은 가정값(ASSUME)에 기대는 추정이므로, 개발 중 `npm run sim` 봇 시뮬레이션으로 2차 검증한다 (BUILD_PLAN 6단계).

## 1. 한 줄 요약
고양이 손님이 끝없이 몰려드는 작은 국밥집을 탭만으로 정신없이 굴리는 3D 쿼터뷰 하이퍼캐주얼 타이쿤. 회전율이 생명이다. 번 돈으로 직원·설비·메뉴·연구·홍보에 투자해 **소상공인 → 미슐랭**까지 키우면 엔딩. 며칠 만에 미슐랭을 찍었는지가 결과이자 자랑거리다.

## 2. 확정된 방향
| 항목 | 결정 |

| 템포 | 모든 것이 빠르다. 손님 도착, 조리, 걷기, 먹기, 화면 전환까지. 바쁜 순간엔 정신없어야 한다 |

| 플랫폼 | 모바일 세로 우선 웹게임. PC는 화면 가운데 세로 캔버스(최대 폭 480px) + 양옆 배경 |

## 3. 하루의 흐름
```
[정비 시간] → 다음 영업하기 → "영업 시작!"(1초) → [영업 120초] → 마감(입장 중단) → 남은 손님 처리(마지막 손님이 다 먹고 나가고 그 테이블을 치워 계산할 때까지) → [정산] → 확인 → [정비 시간] …
```
- 영업 시간: 실제 **120초** = 게임 시계 11:00 → 21:00. 상단 바에 진행도 표시.
- 마감 후: 웨이팅 줄은 조용히 해산(페널티 없음). 앉은 손님은 계속 처리하고, 마지막 손님이 다 먹고 나간 뒤 그 테이블까지 치워 계산해야 정산으로 넘어간다(2026-11-10 변경). 안전장치: 마감 후 90초가 지나면 남은 손님은 페널티 없이 퇴장, 남은 동전은 자동 수금.
- 일시정지 버튼 있음. 배속 없음(이미 빠르다).
- 한 바퀴(영업 + 정산 + 정비) 목표 시간 약 2.7분. 정산과 정비는 짧게 끝낼 수 있어야 한다(12장, 16장).

## 4. 핵심 루프 (한 테이블 기준)
`손님 입장 → 주문 → 조리 → 서빙 → 식사 → 퇴장 → 청소·수금 → 설거지`

### 4.1 손님 입장
- 손님은 **팀** 단위. 팀 인원 가중치: 1명 30, 2명 34, 3명 14, 4명 12, 5명 4, 6명 3, 7명 2, 8명 1. **현재 가게의 가장 큰 테이블보다 큰 인원은 뽑지 않는다.**
- 입구에서 **인원이 들어가는 가장 작은 빈 테이블**로 걸어간다(5칸/초). 치워지지 않은 테이블은 빈 테이블이 아니다.
- 맞는 자리가 없으면 가게 앞 **웨이팅 줄**에 선다. 최대 6팀, 넘치면 그냥 지나간다(놓친 손님 집계).
- 자리가 나면 줄의 맨 앞부터 확인해 **그 자리에 들어가는 첫 팀**이 입장(작은 팀 새치기 허용).
- 웨이팅 인내심 = `10초 + 5초 × 가게 별점` (별점 0 → 10초, 5.0 → 35초). 다 되면 화내며 떠난다(리뷰 없음, 놓친 손님 집계).
- 도착 간격: 분당 팀 수 `λ = (7.0 + 3.0 × 가게별점) × (1 + 홍보 보너스 합) × 티어 배수`, 지수분포 간격, 최소 간격 0.8초.

### 4.2 주문
- 착석 즉시 대표 고양이가 손을 흔들며 "주문!" 말풍선. **플레이어가 테이블을 탭** → 주문 접수 → 말풍선이 메뉴 아이콘으로 바뀐다.
- 키오스크가 있으면 착석 0.6초 후 자동 접수.
- 1인 1메뉴. 메뉴 선택 가중치(해금된 것만): 순대국밥 50, 얼큰순대국밥 35, 수육 15 (**수육은 2인 이상 팀만**, 팀당 최대 1개).
- 단체는 말풍선 하나에 아이콘 여러 개 + 남은 수량(×2). 서빙될 때마다 수량이 줄어든다.

### 4.3 조리
- **빈 화구 탭** → 화구 위로 메뉴 원형 버튼이 펼쳐짐(0.12초) → 메뉴 탭 → 조리 시작. 각 버튼에 "지금 홀에서 기다리는 그 메뉴 수" 배지.
- 해금 메뉴가 1개뿐이면 화구 탭 즉시 조리 시작(선택 생략).
- 조리 시작 시 **깨끗한 그릇 1개** 소모. 그릇이 0이면 화구가 흔들리며 "그릇이 없어요" 토스트.
- 조리 시간(플레이어 기준): **순대국밥 3초, 얼큰순대국밥 3.5초, 수육 5초.**
- 완료 → 노란 "완료!" 알림이 통통 튀고 **3초 탄내 카운트다운**(빨간 링). 그 안에 탭 → 배식대로 이동.
- 3초 초과 → **탐**. 검은 연기, 음식 폐기, 그릇은 개수대로(개수대가 꽉 차 있으면 자리가 날 때까지 화구가 "탄 냄비" 상태로 막힘). 탄 국밥 수 집계.
- 배식대 칸 수 = 화구 수 × 2. 배식대가 꽉 차면 완료 국밥을 옮길 수 없다(그대로 두면 탐).

### 4.4 서빙
- **배식대의 국밥을 탭** → 그 메뉴를 기다리는 테이블 중 **가장 오래 기다린 테이블**로 날아간다(1탭 서빙).
- 특정 테이블로 보내고 싶으면 **국밥을 끌어서 테이블에 놓기**(드래그 서빙). 메뉴가 안 맞으면 튕겨 돌아온다.
- 기다리는 테이블이 없으면 국밥이 살짝 흔들리고 그대로 남는다.
- 주문 순서는 상관없고 메뉴만 맞으면 된다. 배식대 국밥은 공용이다.

### 4.5 인내심과 이탈
- 테이블 인내심 = **`22초 + 3초 × (주문 수 − 1)`**. 착석 순간부터 **마지막 그릇이 놓일 때까지** 하나의 게이지.
- 50% 경과: 게이지 노랑 + 한 마리가 발을 탁탁 구름("탁탁" 효과선).
- 80% 경과: 게이지 빨강 + 말풍선 흔들림.
- 100%: 화난 얼굴로 팀 전체 퇴장 → **리뷰 0.0** 1건, 화난 손님 집계. 이미 놓인 그릇은 남아 테이블이 지저분해지고, 치우면 돈 0원, 그릇은 개수대로.

### 4.6 식사와 퇴장
- 그릇이 놓인 손님부터 각자 먹기 시작(**5초**). 팀의 마지막 손님이 다 먹으면 다 같이 일어나 나간다. 나가는 순간 리뷰 1건 생성(5장).
- 나간 테이블 위에 빈 뚝배기 + 통통 튀는 동전.

### 4.7 청소·수금
- **동전이 뜬 테이블 탭** → 결제 금액이 들어오고(동전이 HUD로 0.35초에 빨려 감), 그릇 전부가 개수대로.
- 개수대 빈 칸 < 그 테이블 그릇 수면 **치울 수 없다**: 동전이 회색, 탭하면 "개수대가 꽉 찼어요".
- 치워진 테이블만 다음 손님이 앉을 수 있다.

### 4.8 설거지
- **개수대 탭 1번 = 그릇 1개** 세척(쿨다운 0.15초). 씻은 그릇은 화구 옆 그릇 더미로 날아간다.

### 4.9 그릇 순환 (핵심 자원)
`그릇 더미 → 화구(조리) → 배식대 → 테이블 → 개수대 → 설거지 → 그릇 더미`
시작 그릇 6개, 시작 개수대 8칸.

## 5. 맛, 친절도, 별점

### 5.1 맛 레벨 (1~10)
| 누가 조리 | 맛 레벨 |
|---|---|
| 주방장 없음, 플레이어 | `1 + floor(맛 연구 레벨 / 2)` |
| 주방장 | `주방장 실력 + 맛 연구 레벨` (최대 10) |
| 주방장이 있을 때 플레이어 | `max(1, 고용 중인 주방장 중 최고 맛 레벨 − 1)` |

실제 판매가 = `메뉴 가격 × (1 + 0.04 × (맛 레벨 − 1))` (맛 10이면 +36%). 그릇마다 조리 순간의 맛 레벨이 기록된다.

### 5.2 친절도 (0~10)
그릇을 손님에게 전달한 주체의 친절도. 플레이어 2, 서버는 등급별(6장). 팀 리뷰에는 그 팀에 전달된 그릇들의 평균 친절도.

### 5.3 리뷰 한 건의 점수
```
T = 팀이 받은 그릇들의 평균 맛 레벨, K = 평균 친절도
p = (마지막 그릇이 놓인 시점의 경과 시간) / 테이블 인내심
속도 계수 F = 1.0                       (p ≤ 0.4)
             1.0 − 0.6 × (p − 0.4) / 0.6 (p > 0.4, p=1이면 0.4)
상한 C = 0.5 + 4.5 × (0.6 × (T−1)/9 + 0.4 × K/10)
기대값 Q = C × F
샘플링: 80% → Q + 삼각분포(−0.3 ~ +0.3)
        20% → Q ± 균등분포(0.4 ~ 0.9)  (부호 반반, "양극단 리뷰")
최종 = clamp(0, 5) 후 소수 첫째 자리 반올림
```
- 시작 상태(T=1, K=2, 아주 빠르게)면 C = 0.86 → 대부분 0.6~1.2점, 가끔 0.0~0.5점.
- 화나서 나간 팀 = 0.0점 리뷰.

### 5.4 가게 별점
- **최근 리뷰 50건의 평균**, 소수 첫째 자리 표시. 리뷰가 없으면 0.0. (50건이면 하루 반~이틀치라 하루 실수로 무너지지 않는다)
- 리뷰가 생기면 HUD 별점 옆에 리뷰 점수가 작게 떠오른다(초록: 현재 별점 이상, 빨강: 미만).

## 6. 직원
정비 시간에만 고용·해고. 고용할 때 **계약금 = 일당 × 2.5일**(5,000원 단위)을 바로 내고, **일당**은 정산 때 지급. 승급은 계약금 차액, 강등·해고는 무료(2026-11-10 변경, 근거 BALANCE_LOG "직원 가격"). 직원은 영업 중 3D 고양이로 직접 돌아다닌다.

### 6.1 등급 공통
| 등급 | 고용 가능 조건 | 소품 색 |
|---|---|---|
| 견습 | 처음부터 | 기본 |
| 일반 | 처음부터 | 기본 |
| 베테랑 | 동네 맛집 이상 | 은색 배지 |
| 장인 | 줄서는 맛집 이상 | 금색 배지 |

### 6.2 주방장 (최대 3명)
| 등급 | 조리 속도 배수 | 맛 실력 | 일당 |
|---|---|---|---|
| 견습 | ×1.0 | 2 | 50,000 |
| 일반 | ×1.25 | 3 | 75,000 |
| 베테랑 | ×1.5 | 5 | 100,000 |
| 장인 | ×1.8 | 6 | 135,000 |
- 한 명이 화구 **최대 2개**를 동시에 맡는다. 끓일 화구 앞으로 옆걸음으로 옮겨 가서(4칸/초) 조리를 시작한다. 아직 조리·배식대·서빙 중이 아닌 주문 중 가장 오래된 것부터.
- 주방장 조리는 **절대 타지 않는다**(완료 즉시 배식대로. 배식대가 꽉 차면 화구 위에서 대기, 이때도 안 탐).
- 플레이어도 남는 화구로 직접 조리 가능.

### 6.3 서버 (최대 2명)
| 등급 | 이동 속도(칸/초) | 한 번에 나르는 그릇 | 친절도 | 일당 |
|---|---|---|---|---|
| 견습 | 3.5 | 1 | 4 | 40,000 |
| 일반 | 4.5 | 2 | 6 | 65,000 |
| 베테랑 | 5.5 | 2 | 8 | 85,000 |
| 장인 | 6.5 | 3 | 10 | 115,000 |
- 우선순위: ① 배식대 국밥 서빙 ② 주문 받기(키오스크 없을 때) ③ 동전 뜬 테이블 치우기(개수대 여유 있을 때).
- 동작 하나(집기·놓기·주문·치우기)는 0.2초. 걸어서 이동(그리드 경로). **손님이 우선**: 서버가 손님 길을 막으면 옆으로 비켜 선다. 등급이 높을수록 길을 잘 찾는다(손님 이동 예측 0/0.4/0.8/1.2초, 막히면 다시 길 짜기 0.45/0.3/0.2/0.12초).

## 7. 시설
| 항목 | 단계와 비용 |
|---|---|
| 화구 | 시작 2개 → 3개 60,000 → 4개 120,000 → 5개 200,000 → 6개 300,000 (화구 칸은 가게 단계마다 3/4/5/6칸) |
| 그릇 세트 | +2개당 25,000, 최대 30개 |
| 개수대 | 소형 8칸(시작) → 중형 14칸 50,000 → 대형 22칸 100,000 → 업소용 32칸 200,000 |
| 키오스크 | 120,000 (주문 자동 접수) |

| 가게 단계 | 테이블(인원) | 비용 | 하루 임대료 |
|---|---|---|---|
| 1 기본 | 2·4·4 (3개) | — | 20,000 |
| 2 | +4·2 (5개) | 160,000 | 35,000 |
| 3 | +6·4 (7개) | 280,000 | 60,000 |
| 4 | +8·4·4 (10개) | 450,000 | 110,000 |
확장하면 벽이 밀려나며 바닥이 넓어지는 연출(0.6초). 카메라는 가게 전체가 들어오도록 줌아웃하고, 화면보다 커지면 드래그 이동·핀치 확대(0.8~1.6배) 허용. 새 테이블 배치는 ART.md 8장 겹침 규칙을 따른다.

공과금(정산 시): `2,000 + 화구 수 × 2,000`.

- **귀빈 팀**: 4인, 선글라스와 금목도리, 영업 시작 20~60초 사이 도착, 웨이팅 줄을 건너뛰고 다음 빈 4인석에 앉는다. 귀빈 리뷰는 가게 별점에 10건으로 계산. **귀빈 리뷰 4.5점 이상이면 "귀빈 인정"**(미슐랭 조건). 실패하면 다시 부를 수 있다.

## 11. 식당 티어
정산 직후 판정. 조건: **가게 별점**과 **최근 3일 평균 매출**(총매출). 강등 없음.
| 티어 | 별점 | 3일 평균 매출 | 손님 배수 | 해금 |
|---|---|---|---|---|
| 소상공인 | — | — | ×1.0 | — |
| 동네 맛집 | 1.5 | 160,000 | ×1.1 | 베테랑 직원, 수육, 구글 광고 |
| 줄서는 맛집 | 2.4 | 400,000 | ×1.25 | 장인 직원, 유튜브 |
| 블루리본 | 3.4 | 800,000 | ×1.4 | TV 출연, 간판 리본 장식 |

티어가 오르면 전체화면 축하 연출(2초, 탭하면 넘김) + 입구 간판 변화. 정비 화면에 다음 티어까지 진행도 바 두 개(별점, 매출)와 남은 조건.

### 11.1 진행 모델 결과 (`python tools/progression_model.py`) + 봇 시뮬레이션 (`npm run sim`)
비용·조건은 6단계 봇 시뮬레이션으로 다시 맞췄다(2026-11-10, 근거는 `docs/BALANCE_LOG.md`). 템포 수치(시간·속도)는 그대로다.

**봇 시뮬레이션 (실제 게임 규칙, 20시드 중앙값, `docs/balance-report.md`, 2026-11-10 재조정)** — 플레이 시간 = 영업 120초 + 마감 뒤 정리 + UI 연출(데이터 값) + 정비 15초 + 구매당 4초
| 봇 | 미슐랭 | 누적 시간 |
|---|---|---|
| 평균 (탭 1.3/초) | **22일** | **약 60분** |
| 아주 느린 편 (0.9/초) | 27일 | 약 74분 |
| 숙련 (2.0/초) | 21일 | 약 57분 |

**진행 모델 (가정값 그대로, 같은 비용·계약금)** — 평균(1.3) 22일 60분, 2.0/초 20일 55분, 1.0/초 25일 67분, 0.9/초 27일 73분. 봇과 1~2일 차이.
- 모델이 봇보다 5일쯤 빠른 이유: 모델은 테이블 한 바퀴 12초(입장 1.5초, 서빙 1.2초)와 서버 왕복 8칸을 가정하지만, 실제 구현은 걷는 길·통로 막힘 때문에 한 바퀴 약 20초(입장 3.5초, 착석→서빙 9~10초), 서버 왕복 약 16칸이다. 그래서 하루 판매 상한이 모델 166그릇 → 실제 약 125~135그릇이고, 서버가 다 못 나르는 만큼 플레이어가 직접 서빙(친절도 2)해 후반 별점이 4.3~4.5 사이에서 흔들린다. 미슐랭 날짜의 시드별 차이(16~24일)는 대부분 "별점 4.5 이상인 날"을 기다리는 시간이다.
- 평균 플레이어 기준 일별(봇, 시드 1000): 1일차 판매 28그릇·매출 25만·순익 13만 → 10일차 87그릇·117만 → 15일차 132그릇·195만 → 20일차 124그릇·181만.

## 12. 정산 화면
마감 후 영수증 종이가 위에서 내려오고 항목이 줄당 0.15초로 찍힌다(탭하면 한 번에 전부). 전체 3초 이내.
```
총매출 (판매 N그릇, 맛 프리미엄 포함)        +
재료비                                    −
직원 일당 (이름·등급별 한 줄씩)              −
임대료                                    −
공과금                                    −
홍보비 (어제 정비 시간에 산 것)              −
───────────────────────────────
순수익                                    = (음수면 빨강)
```
통계: 받은 손님 팀/명, 놓친 손님, 화난 손님, 탄 국밥, 오늘 리뷰 평균, 가게 별점 변화(▲▼), 티어 진행도.
버튼: **확인**(정비 시간으로) · **자랑하기**(오늘 카드).
돈이 마이너스여도 게임오버는 없다. 구매만 막히고 경고 표시.

## 13. 엔딩과 결과 페이지
**미슐랭 판정이 난 정산 직후** 엔딩.
1. 엔딩 연출(약 6초, 탭하면 넘김): 문 위에 별 3개 현판이 달리고, 가게 안의 모든 고양이(직원·손님)가 일어나 만세, 색종이, 팡파르.
2. **결과 페이지**
   - 큰 제목: **"N일 만에 미슐랭!"** (N = 미슐랭을 찍은 영업 회차)
   - 실제 플레이 시간: 영업·정산·정비 시간 누적(일시정지·탭 비활성 시간 제외), "57분 12초" 형식
   - 칭호(일수 기준): 16일 이하 "국밥의 신" · 19일 이하 "전설의 국밥 장인" · 22일 이하 "미슐랭 셰프" · 26일 이하 "골목의 자랑" · 그 이상 "끈기의 국밥집"
   - 성장 타임라인: 티어별 도달일(소상공인 1일 → … → 미슐랭 N일) 가로 막대
   - 누적 기록: 받은 손님, 판매 그릇, 총매출, 최고 하루 매출, 탄 국밥, 화난 손님, 최종 별점, 직원 구성 고양이 얼굴
   - 버튼: **자랑하기** · **계속 영업하기**(무한 모드, 미슐랭 유지) · **처음부터 다시**
3. **공유**
   - 결과 카드 이미지(1080×1350, 캔버스): 가게 이름, "N일 만에 미슐랭", 칭호, 플레이 시간, 별점, 손님 수, 고양이 일러스트.
   - 공유 링크: `https://ovencub.github.io/guckbob/?r=<결과>` — `<결과>` 는 `{v:1, n:가게이름, d:일수, m:분, s:별점, c:손님수, t:칭호코드}` 를 JSON → base64url. 받는 쪽은 이 값을 검증(가게 이름 12자, 숫자 범위)하고 텍스트로만 표시.
   - 이 링크로 들어온 친구는 첫 화면에 **"OO 국밥의 기록: N일 만에 미슐랭"** 도전장 카드 → **"나도 도전하기"** 버튼으로 새 게임 시작. 친구가 엔딩을 보면 결과 페이지에 "도전장 기록보다 X일 빠름/느림" 표시.
   - 공유 방법: Web Share API(이미지 파일 + 링크) → 안 되면 이미지 저장 안내 + 링크 복사.
- 정산 화면의 "자랑하기"는 그날 카드(N일차, 티어, 매출, 별점)를 같은 방식으로 공유.
- 가게 이름: 첫 실행 때 입력(기본 "고양이 국밥"), 정비 화면에서 변경 가능. 간판과 결과 카드에 반영.
- `index.html` Open Graph 메타 + `public/og.png`(1200×630).

## 14. 튜토리얼
1일차 첫 손님 3팀은 스크립트: 손가락 포인터가 테이블 → 화구 → 완료 알림 → 배식대 국밥 → 동전 → 개수대 순으로 짚는다. 첫 3팀은 인내심 2배. 건너뛰기 버튼. 60초 안에 끝나야 한다.
