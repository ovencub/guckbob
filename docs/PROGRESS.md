### 오류 분석 — 5단계 e2e 겹침 13건 (손님 몸→의자 0.19, 서버 꼬리→배식대 0.05)
- **증상:** 직원 풀세트·4단계 가게 하루에서 손님 한 마리 몸·양발이 의자를 깊게 관통, 서버 꼬리가 배식대에 0.05.
- **원인 추정 1:** 의자에 올라타는 중(enterSeat)인 손님의 팀이 화나서 나가면 상태가 바로 toExit 이 된다. 그 순간 고양이는 자기 의자 바로 앞인데, "자기 의자 제외"는 앉기 관련 상태에서만 적용 → 자기 의자를 뚫은 것으로 집계. 게다가 toExit 은 정적 장애물 검사를 하므로 그 자리에서 못 움직이고 끼어 있다가 뿅 사라진다.
- **원인 추정 2:** 서버가 배식대 앞 0.5칸에서 돌아설 때 꼬리(뒤로 0.62 + 굵기 0.05)가 배식대 상자를 쓸고 지나간다. 걷는 고양이가 카운터·벽에서 떨어지는 거리 0.5 < 꼬리 0.67.
- **근거:** 관통 부위가 `몸·왼발·오른발→stool`(같은 고양이 한 마리) 과 `꼬리→counter`. 의자 쪽은 의자에 올라타는 높이(0.235)에서 발이 상자 안(0.1 = 발 반지름 전체)인 값과 일치.
- **수정 계획:** ① 올라타는 중·앉는 중에 떠나게 되면 의자에서 내려와 진입 지점으로 되돌아가는(exitSeat) 경로를 탄다. ② 걷는 고양이 ↔ 카운터·벽 간격 = 꼬리 길이 0.67, 서버가 배식대 앞에 서는 거리 0.7. 레이아웃 검증 다시.
- **수정 결과:** ① 떠날 때 의자 위 손님은 exitSeat 로 내려옴 ② 카운터·벽 간격 0.67, 배식대 앞 서버 0.7, 테이블 상판 0.42(든 앞발), 의자 0.53, 좌석 진입 지점은 0.9칸만(0.84 지점에서 돌아서면 꼬리가 자기 의자를 쓸어서), 직선 좌석 출입 구간에서는 옆걸음 금지. 레이아웃 4단계 재검증 OK(2인석 x −1.35→−1.2, 뒤 왼쪽 4인석 z −0.55→−0.5). e2e 겹침 0.02 초과 0건(최대 0.020 = 주방장 앞발↔조리대, 허용 한계 안).
- 테스트 65개 통과(`tests/staff.test.ts` 8개 추가: 주방장 화구 2개 상한·속도·맛, 서버 우선순위·주문·친절도, 개수대 꽉 참이면 안 치움, 설거지 알바 속도, 플레이어가 먼저 하면 일 내려놓기).

### 오류 분석 — 늦은 게임 별점 정체 (~4.3), 서버 처리량 부족
- **증상:** 직원 풀세트에서도 평균 친절도 K ≈ 6.6~8, 별점 4.1~4.4. 서버 두 명 근무 시간이 이동으로 꽉 참(하루 240초 중 ~240초), 그중 ~30%는 막혀 대기.
- **원인 추정:** ① 서버가 들고 있는 그릇의 배달 대상(주문)을 예약하지 않는다(`OrderItem.reserved` 를 아무도 안 씀). 같은 메뉴를 든 두 서버가 같은 "가장 오래 기다린 테이블"로 가고, 늦게 온 쪽은 헛걸음 후 재탐색. ② (확인됨, 1차 수정) 다 먹은 손님 무리가 출구까지 걸어 나가며 통로를 막음 → 행복 퇴장은 통로로 나와 뿅.
- **근거:** `grep reserved src/sim` — 선언과 읽기만 있고 쓰는 곳 없음. 막힘 위치 표본의 상위가 `deliver@… by server:walk`.
- **수정 계획:** 배달 대상을 정할 때 들고 있는 그릇마다 주문 하나씩 서버 이름으로 예약, 도착하면 예약한 주문에 놓고, 일을 내려놓으면 예약 해제. 플레이어 탭 서빙은 예약 안 된 주문부터.
