# ZZIK SIN (찍신) — 설계 의도 문서

> 이 문서는 설계 의도와 방향성을 정리한 기획 자료입니다.
> Claude Code에 전달할 때는 이 문서를 참고자료로 제공하고,
> Claude Code의 plan mode에서 실제 코드베이스/기술스택 기준으로
> 구체적인 구현 스펙(spec.md)을 별도로 작성하도록 요청하세요.
> 예: "이 문서와 questions.json을 참고해서 현재 폴더 구조에 맞는 구현 계획을 plan mode로 세워줘"

---

## 1. 프로젝트 개요

**한 줄 정의**: 인터넷에서 자주 설전이 붙는 정치·경제·사회 이슈를 공식 통계로 "찍어서" 맞히는 웹 게임.

**왜 만드는가**
- 사람들은 미디어·커뮤니티에서 접한 인상으로 사회를 판단한다. 직접 숫자를 예측해 본 뒤 실제 값과의 차이를 보면 "내가 생각했던 것과 다르네?"라는 경험이 생긴다.
- 정답만 보여주는 팩트체크 기사보다, **먼저 틀려보는 경험**이 인식을 바꾸는 힘이 크다는 것이 핵심 가설.

**레퍼런스**: guessdash.com의 Extraplot(끊긴 차트의 이후 추세를 그리면 실제 선이 그려짐), Piecemeal(파이 조각을 드래그해 실제 비율에 맞춤).

**타겟**: 커뮤니티·SNS에서 사회 이슈에 관심 있는 20~40대. 결과 공유로 유입되는 사용자.

**핵심 가치**
1. 짧다 — 한 판 5문제, 2~3분.
2. 놀랍다 — 통념과 실제의 차이가 큰 문제를 우선 배치.
3. 공정하다 — 어느 진영의 통념이든 깨지도록 문제를 고르고, 모든 문제에 "이 숫자만으로 말할 수 없는 것"을 함께 보여준다.

---

## 2. 범위

### MVP (1차 프로토타입)
- 문제은행 100문제(`questions.json`)에서 **한 판 5문제 랜덤 출제**
- 문제 형식 3종 입력 UI: 숫자 찍기(슬라이더) / 파이 나누기 / 추세선 그리기
- 문제별 결과 화면: 내 답 vs 실제 값, 점수, 통념(myth), 해설, 주의점(caveat), 출처 링크
- 최종 결과 화면: 총점, 문제별 오차 요약, 결과 공유(이미지 또는 텍스트)
- 모바일 우선 (한 손 드래그 조작)

### 추후 기능
- 오늘의 문제(데일리 고정 5문제, 전 사용자 동일) + 다른 사람들의 평균 예측 분포 공개 ("사람들은 평균 ○○%로 예상했어요") — 이 기능이 생기면 콘텐츠 가치가 크게 커짐
- 분야 선택 플레이(범죄만, 경제만 등)
- 랭킹, 연속 플레이 스트릭
- 문제 신고/출처 이의 제기 버튼
- 새 통계 발표 시 문제 업데이트 운영 도구

## 3. 핵심 시스템 설계 의도

### 3-1. 데이터 (`questions.json`)
- 문제은행은 코드와 분리된 데이터 파일로 관리한다. 문제 추가·수정이 코드 수정 없이 가능해야 한다.
- 공통 필드: `id, type, category, title, question, myth, explanation, caveat, source{name,url}, dataYear, verification, note`
- 형식별 필드
  - `number`: `answer, unit, slider{min,max,step}, tolerance`
  - `pie`: `slices[{label,value}]` (합계 100)
  - `line`: `series[{x,y}], cutoffX, unit, yRange[min,max]` — cutoffX까지는 보여주고 이후 구간을 사용자가 그림
- `verification`: `verified`(원문 확인) / `partial`(일부 과거값 재확인 필요) / `computed`(원자료로 직접 계산, `note`에 계산식)
- `build_questions.py`가 문제은행의 원본이며, 실행하면 파이 합계·컷오프 전후 점 개수·정답의 슬라이더 범위·ID 중복을 검사한 뒤 JSON을 만든다. **문제 수정은 이 스크립트에서 하고 JSON을 재생성**하는 흐름을 의도한다.

### 3-2. 출제 로직
- 한 판 5문제를 뽑되, 가능하면 **분야가 겹치지 않게**, **형식이 최소 2종 이상 섞이게** 뽑는다.
- `verification = partial`인 문제는 출시 전까지 별도 플래그로 숨기거나 표시할 수 있게 한다.
- 같은 세션에서 최근에 푼 문제는 다시 나오지 않게 한다.

### 3-3. 입력 UI 의도
- **숫자 찍기**: 슬라이더 + 직접 입력. 슬라이더 범위는 정답을 짐작하게 하지 않도록 넉넉하게 잡혀 있다(데이터에 지정).
- **파이 나누기**: 조각 경계를 드래그해 비율 조정, 각 조각의 %를 실시간 표시. 시작 상태는 균등 분할.
- **추세선 그리기**: cutoffX까지 실제 선이 그려진 차트에서, 이후 구간을 손가락/마우스로 그린다. 제출 시 실제 선이 애니메이션으로 이어 그려지는 순간이 이 게임의 하이라이트다.

### 3-4. 채점 의도 (모든 형식 0~100점으로 정규화)
- 숫자: 오차율 기반. 정답에 가까울수록 점수가 높되, `tolerance` 안이면 만점에 가깝게. 음수·0 근처 정답(예: 재정수지 적자)도 공정하게 다루도록 슬라이더 범위 대비 오차를 함께 고려.
- 파이: 조각별 절대 오차 합을 기준으로 감점(Piecemeal 방식).
- 추세선: cutoffX 이후 실제 점들의 x에서 사용자 선의 y값을 읽어 yRange 대비 평균 오차로 채점. 방향(증가/감소)을 맞히면 가산점을 주는 것도 검토.
- 구체적 공식은 Claude Code가 plan mode에서 결정하되, "체감상 공정한지"를 플레이 테스트로 조정한다.

### 3-5. 결과 화면 의도 (가장 중요)
순서: **내 답 vs 실제 값 → 통념(myth) → 해설 → 이 숫자만으로 말할 수 없는 것(caveat) → 출처**
- caveat를 생략하지 않는다. 이 게임이 한쪽 진영의 선전 도구가 되지 않게 하는 장치다.
- 출처는 반드시 클릭 가능한 링크로.

### 3-6. 중립성 원칙 (콘텐츠 운영 규칙)
- 한 이슈에 반대 방향 통념을 깨는 문제를 짝지어 둔다. 예: 외국인 범죄율(Q001) ↔ 외국인 살인 피의자 증가(Q002), 외국인 건보 1조 흑자(Q039) ↔ 중국 국적 409억 적자(Q040), 국민부담률 OECD 최하위(Q030) ↔ 국가채무 증가(Q028).
- 해설 문장에 가치 판단("~해야 한다", "잘했다/못했다")을 넣지 않는다.
- 여론조사·지지율·특정 정치인 평가는 문제로 쓰지 않는다(정당·인물 편향 위험). 투표율·인구·제도 통계만 쓴다.

## 4. 개발 순서 및 근거

1. **데이터 로딩 + 숫자 찍기 1종으로 5문제 한 판 완주** — 73문제가 숫자형이라 가장 빨리 "게임이 되는지" 확인 가능. 결과 화면(해설·caveat·출처) 구조를 여기서 확정.
2. **추세선 그리기** — 가장 인상적이지만 구현 리스크(터치 드로잉, 채점)가 가장 크므로 두 번째에 검증.
3. **파이 나누기** — 드래그 UI 구현.
4. **출제 로직 고도화** (분야·형식 섞기, 중복 방지) + 최종 결과/공유 화면.
5. **모바일 플레이 테스트 후 채점 공식 튜닝**.
6. **출시 전 데이터 점검**: `partial` 24문제의 과거값을 KOSIS·선관위 등 원자료로 재대조.

## 5. 미해결 질문 / 추후 결정

- 게임 이름 표기: "찍신" 한글 로고 vs "ZZIK SIN" 영문
- 공유 결과물 형식: 이미지 카드 vs 텍스트(이모지 그리드, Wordle식)
- 데일리 모드와 평균 예측 분포 공개를 MVP에 넣을지 (서버/저장소 필요 여부가 갈림)
- 통계 갱신 주기: 대부분 연 1회 발표 → 매년 상반기 일괄 업데이트 운영 여부
- `partial` 문제를 출시 시 숨길지, "재확인 중" 배지를 달고 노출할지
